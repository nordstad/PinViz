## Design Context

### Users
PinViz documentation serves makers and hobbyists wiring Raspberry Pi and ESP projects, Python developers integrating the library, and AI-assistant users working through the MCP server. Visitors use examples to quickly find a diagram that matches their board or feature, understand what it demonstrates, and reach a runnable configuration.

### Brand Personality
Practical, confident, and clear. The documentation should make hardware-diagram generation feel approachable without obscuring technical precision.

### Aesthetic Direction
Use a documentation-first, light-or-dark adaptive presentation that prioritizes actual diagrams, readable code, and direct navigation over decorative product marketing. Example discovery should resemble a useful visual reference library rather than a long index of text links.

### Design Principles
1. Make diagrams and their distinguishing features visible before users need to choose a page.
2. Organize examples by the way users search: board, task, and capability.
3. Keep each example's route to a runnable configuration direct and obvious.
4. Preserve technical accuracy and warnings alongside visual polish.
5. Use progressive disclosure: scan visually first, then open the full explanation and YAML.
